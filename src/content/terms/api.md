## ① 非エンジニア向けのざっくり概要

別のシステムへ頼みごとをするときの窓口。

プログラム同士がデータを渡したり処理を依頼したりするときの決まりです。Web では HTTP とセットで語られることが多いです。

イメージ補足：レストランの「メニュー」と「厨房へのオーダー方法」に近いです。

## ② ちょっとだけ詳しく

- Why｜何のために使うか: 画面を介さずシステム同士を直接つなぎ、データ取得や処理依頼を自動化するため。
- Who｜誰（どんな役職・スキルセットの人）が主に使うか: 開発者、システム連携を検討する情シス・企画担当、外部サービス導入の担当者。
- When｜どんな場面で使うか: 受発注と在庫、SaaSと社内システムなど、別々のシステムを連携させたいとき。
- Where｜どこで動く/使うか（社内・クラウド・端末など）: Web（クラウド）上のやり取りが中心で、社内システム同士でも使う。
- How｜どうやって使うか: 1) 呼び出し側が URL と方法（GET/POST など）を指定 -> 2) 認証情報や必要データを送る -> 3) 受け側が処理して結果を返す -> 4) 結果やエラーに応じて次の処理を決める。

- できること｜導入後の実務効果:
  - 手作業の転記をなくし、システム間の連携を自動化できる
  - 外部サービス（地図・決済・AIなど）の機能を自社サービスに組み込める
  - 更新遅れやミスを減らし、データを最新に保てる

- よくある誤解｜似た用語との差分: GUIと混同されがちだが、GUIは「人の操作」、APIは「機械同士の連携」で連携の主体が違う。
